# ParkEase — Frontend + Backend + Database

India's peer-to-peer parking marketplace. One project containing: **frontend** (HTML/CSS/JS), **backend** (Node.js + Express), and **database** (PostgreSQL hosted on Supabase).

## 2. Setup and Running Steps

1. **Install Node.js 18+** (nodejs.org). Check the installation using `node -v`.

2. **Create a Supabase project** (supabase.com, free): Create a new project and remember your database password.

3. **Get the connection string:**
   Project Settings → Database → Connection string → **URI** → Select **Session pooler**.

   Replace `[YOUR-PASSWORD]` with your actual database password. If your password contains special characters like `@ # / ?`, URL-encode them (`@` → `%40`).

4. **Open the `.env` file** and paste this connection string after `DATABASE_URL=`. Do not change anything else.

5. Open the terminal inside this project folder and run:

   ```bash
   npm install          # Install libraries
   npm run db:check     # RUN THIS FIRST: checks whether the database is connected and explains any errors
   npm run setup        # Copy vendor libraries + create tables + add demo listings
   npm start            # Start the server (you should see "✓ Database connected" at startup)
   ```

6. Open **http://localhost:3000** in your browser.

To use PostgreSQL installed locally on your laptop, set the following in `.env`:

```env
DATABASE_URL=postgresql://postgres:password@localhost:5432/parkease
DATABASE_SSL=false
```

First, create the database using `createdb parkease`.

## 3. Complete Request Flow (Explain This in Interviews)

When a user clicks "Reserve":

1. `public/app.js` → `api.createBooking()` → `fetch('/api/bookings', POST)`
2. `server.js` → Security checks (CSRF, rate limit) → `routes/bookings.js`
3. `middleware/auth.js` → Verifies the JWT from the cookie → `req.user`
4. `routes/bookings.js` → Validates input using Zod → **Calculates the price on the server** → INSERT
5. `db.js` pool → **Supabase PostgreSQL**
6. The database checks the `no_double_booking` constraint: Is the slot available? If not, error 23P01 is returned → backend sends `409 "slot just booked"`.
7. If everything is successful, the booking is saved, JSON is returned, and the frontend displays "Booking confirmed".

## 5. Security Features Implemented

- **Password security:** Passwords are hashed using **bcrypt** (cost 12). Plain-text passwords are never stored.
- **Login token:** Stored in an **httpOnly + SameSite cookie** (JavaScript cannot access it). Enable `Secure` in production.
- **Input validation:** Every input is validated using **Zod**. **Parameterized SQL queries** prevent SQL injection.
- **XSS protection:** Frontend user input is escaped + CSP header.
- **CSRF protection:** Only JSON requests from the same site are allowed.
- **Rate limiting:** 15 login/register attempts per 15 minutes.
- **Server-side pricing:** Prices are calculated on the server, never trusted from the browser.
- **Double-booking protection:** Prevented at the database level.
- **Supabase RLS ON:** Prevents tables from being accessed through the public anon key.
- **Helmet security headers:** Security headers enabled and `x-powered-by` disabled.

## 7. Common Problems and Solutions

| Error | Meaning / Fix |
|---|---|
| `DATABASE_URL is not configured` | The URL is missing from `.env` or still contains the template value |
| Login shows "Something went wrong" / "Unable to connect to database" | The server is running, but the database is not connected. Run `npm run db:check` to identify the problem |
| `ENOTFOUND` / `ENETUNREACH` | Direct connection uses IPv6. Use the **Session pooler** URL |
| `password authentication failed` | Incorrect password or special characters have not been URL-encoded |
| `self-signed certificate in certificate chain` | Set `DATABASE_SSL=true` in `.env` (the code uses `rejectUnauthorized:false`); better option: use `DATABASE_CA_FILE` |
| `Missing lucide/...` | Run `npm install` first, then `npm run vendor` |
| Icons/map not appearing | `public/vendor/` has not been created. Run `npm run vendor` |
| Design not appearing | The CSS filename must be `styles.css`, not `style.css` |
| `JWT_SECRET missing` | `JWT_SECRET` must be at least 32 characters long in `.env` |
| Immediate logout after login | HTTPS is required in production (cookie `Secure`); also set `TRUST_PROXY=1` |

## 8. Interview Cheat Sheet

- **Frontend vs Backend?** Frontend runs in the browser and is publicly accessible. Backend runs on the server, handles rules, login, payments, and communicates with the database.
- **Why not connect the database directly to the frontend?** Credentials would become public. The backend acts as an intermediary and handles validation + access control.
- **Why SQL?** Booking and payment systems require transactions and table relationships. (`schema.sql`)
- **How is double booking prevented?** Using a database exclusion constraint (`routes/bookings.js` catches error 23P01). Even if two users try simultaneously, only one booking succeeds.
- **What is JWT?** A signed token containing the user's ID. It is stored in a cookie, sent with every request, and verified by `middleware/auth.js`.
- **How are passwords stored?** Using bcrypt hashing, never as plain text.
- **How is SQL injection prevented?** Using `$1, $2` parameterized queries.
- **What is XSS and how is it prevented?** If someone inserts a script into a listing, it could execute in other users' browsers. We escape user input + use CSP.
- **Why is the price not calculated in the browser?** Anyone can modify browser code, so the server calculates the price.
